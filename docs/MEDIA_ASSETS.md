# 联合缓存与媒体资源持久化

`CacheManager` 管理完整音频，`MediaAssetStore` 管理封面、远程歌词和受保护的手动歌词。两者共用 `UnifiedCacheQuota` 的单一磁盘额度、写入准入锁与跨类型 LRU；来源和资源管理仍独立，因而同专辑封面能物理去重。歌单缓存任务按歌曲缓存完整音频并尝试下载封面与歌词（无封面或无歌词不算音频失败）。

`cache_asset_links` 记录歌曲与封面/歌词缓存的关联。缓存页面仅查询有关联的曲目，展开歌曲可分别查看音频、封面和歌词引用字节数；全局用量按实际文件去重计算，单曲展开的引用量不可直接相加。取消或清理歌曲不会误删其他歌曲仍使用的专辑封面，手动歌词始终受保护。

## 身份与文件布局

当前数据库为 v9，增加 `cache_asset_links` 歌曲资源引用索引。原有音乐源、播放队列、歌单和个人数据不随缓存清理删除；旧版资源不回填关联，请升级后在设置中清理旧缓存。

- 主键是来源 ID 与资源 key，不使用 Token、随机盐、播放票据或完整认证 URL。
- 封面 key 为实际图片 ID、类型和渲染参数（Primary / 800 / 90 / 版本）。有图片 tag 时只用该 tag 判断版本，不因其他歌曲元数据变化而失效；无 tag 时使用 ETag / 修改时间等线索。
- 同一来源内共享相同图片身份；不同来源账户保持隔离。文件按来源哈希和内容 SHA-256 保存，同内容可复用一个不可变文件。
- 歌词按 TrackRef 与解析版本 `lyrics-v3` 建 key，资源版本与更新时间单独记录。手动导入使用独立的 manual key，并标记 pinned。

文件位于应用数据根目录的 `media_assets/objects/<来源哈希>/`；唯一临时文件在 `media_assets/tmp/`。SQLite 记录相对路径、大小、摘要、版本、获取 / 使用 / 过期时间、是否固定、HTTP 验证头。首次读取或文件签名变化时校验长度和摘要；封面实际解码验证，歌词验证 UTF-8 和非空内容。已验证文件按 stat 签名在会话内复用验证结果。

## 读取与更新

1. 优先返回有效本地内容，有效期内不请求服务器。
2. 默认封面 24 小时、远程歌词 6 小时；过期或资源版本变化时先展示旧内容，后台刷新。
3. 相同来源、key、版本和代次的请求合并。较旧代次 / 版本的晚到结果不能覆盖新版本。
4. 封面保留六路网络上限，使用 ETag / Last-Modified 条件请求，304 更新有效期但不换文件；歌词协议暂使用有效期和显式强刷。
5. 远程没有内容短暂退避 1 分钟，临时错误退避 30 秒。失败仍保留可读旧内容，不永久缓存失败；没有旧内容时向页面报告错误。
6. 完整歌词页的刷新 / 重试调用 `forceRefresh`，绕过有效期和退避；手动导入仍保持最高优先级。
7. 提交发生内容 / 版本变化时发送更新事件。封面控件、播放页取色与歌词、完整歌词页按自己的资源 key 更新，无需退出页面。

本地来源继续读取原始文件标签 / LRC；WebDAV 通过共享 WebDavTags 服务主动读取有界音频标签区，并将内嵌封面 / 歌词分别写入此资源缓存；完整音频已缓存则优先本地提取。标签片段从不进入音频 READY。协议、上限和回退见 [WebDAV](WEBDAV.md)。

歌词加载由应用在资源与 API 设置初始化完成后接入播放服务。选中 / 恢复当前曲目，以及播放临近结尾时预取下一首，都会后台尝试加载歌词，无需先打开歌词页。同一 TrackRef 每次应用运行只主动预热一次，来源失效时清除该来源的预热记录；加载不阻塞音频打开，失败不会成为播放错误。仍使用上述缓存、来源取消与退出等待机制，在线歌词补充仍需用户主动启用。

## 写入、配额与生命周期

内容完整接收并验证后写唯一临时文件、flush、rename 为内容文件，再以 SQLite 事务切换索引。磁盘不足、无效响应或中断不会覆盖上一份完整内容。小资源使用 64 MiB 加本次写入量的可用空间预留；磁盘探测不可用时仍由文件大小上限和文件系统写入错误保护，不直接永久禁用缓存。

当前索引中的完整音频、封面和歌词使用同一个 `cache_limit`（Android 默认 5 GiB、桌面默认 10 GiB）。配额在资源写入前统一预留，跨类型按最后访问时间淘汰。专辑共享封面按唯一物理文件计费一次。手动歌词计入实际用量，但带 pinned 标记，不参加自动淘汰或普通清理；读取中的封面/音频受租约保护。

容量统计针对当前索引中的完整文件；下载临时文件和待读取者释放的旧版本另受磁盘安全余量保护，不表示进程任意时刻的目录大小硬上限。

启动时对账：清除 tmp 残片，删除缺文件 / 无来源的失效记录，清理 objects 中无索引文件，再执行配额整理；不在启动时解码整个曲库的封面。来源停用关闭相应读取并失效写入代次；删除来源清理对应资源、迁移标记及旧目录。退出先关闭封面 / 歌词生产任务，再等待资源写入与清理，最后关闭数据库。

## 升级注意

v9 不对原有缓存自动推断歌曲关联。建议用户升级后清理旧版音频、封面和远程歌词，再按需要重新联合缓存歌单。受保护的手动歌词不是普通缓存，不会随这一步清理而丢失。

## 验证

`test/media_assets_test.dart` 覆盖 v5 升级、真实数据库重开、离线读取、SWR、请求合并、晚到版本、写入失败、损坏、启动对账、来源停止、隔离、LRU 和手动保护；`artwork_test`、`lyrics_cache_test` 覆盖服务接入与旧缓存迁移；`media_asset_widgets_test` 覆盖页面自动刷新和读取者释放。

`integration_test/media_assets_test.dart` 仅用合成图片和本机模拟服务，关闭服务器后重建应用服务 / SQLite，验证没有凭据的新实例仍能离线读取、解码并显示内容。它不等同于物理设备强杀 / 存储硬件故障的验收。Windows 临时目录写入受限时可设置进程 TEMP / TMP 和 `SYLPHY_ASSET_TEST_ROOT` 到工程内独立目录，不修改系统权限。Linux 原生验收继续暂缓。
