# Penpal Memory V15 — 有独立人格的轻量音乐笔友

## 目标与边界

保持 SylphyMusic 原有的 SQL 召回、LLM 选曲、写信两阶段、TrackRef 校验和推荐快照。记忆围绕笔友自己的性格与真实相处经历；音乐偏好不是独立画像数据库。不创建常驻 Agent、向量库、Embedding 或定时后台工作；通常仍是两次 LLM 请求。

- **Soul**：稳定、可编辑的笔友人格。默认人格是温和而有独立审美的书信作者，不假装现实生活、亲耳听过音乐或一直等待用户。
- **Self**：每天最多一条由成功主信产生的短反思候选，必须是第一人称写作/审美观点，经客户端长度与禁语约束后才保存；最多留 12 条。
- **Bond**：只记用户实际打开过来信（不等于读完/喜欢），以及用户主动点击“保存给笔友”留下的回复。
- **Episodes**：真实生成过的信件短摘要和近期主题；完整信件仍保存在旧的 `recommendation_letters`。

## 使用体验

每日第一封新信仍为 160–320 字目标（最多 480 字）；当天后续新信改为约 60–140 字的短笺（最多 180 字）。是否主信由当天已存档信件判断，手动刷新也遵守同一规则；不会补发错过时段。模型可自然引用最多一件相关旧事，也可以不引用。打开信件可以选择“给笔友回一句”，只有明确点击“保存给笔友”才存储回复（最多 200 字）。

“每日推荐文案”页和“推荐设置”页都提供“关于我的音乐笔友”，可以停止记录、禁止引用旧事、修改 Soul、删除个别事件或清空全部记忆。关闭记忆仍保留默认笔友人设；关闭“引用往事”时不发送历史事件。清空文案存档时也清理依附于那些信件的自动记忆与已保存回复，不留下孤立的派生记忆。

## SQL v15

新增两张表：

- `penpal_memory_state`：单行 `enabled / recall_enabled / soul_override / updated_at_ms`。
- `penpal_memory_events`：`kind / text / source_key / related_letter_key / topic / created_at_ms / expires_at_ms / pinned`。`kind` 为 `self / letter_written / letter_opened / user_reply`。

已存在的信件不回填虚构的阅读事件和人际事实；v14 → v15 仅建表，不修改既有曲库、收听统计、推荐或存档。普通信件/打开事件分别 45/30 天过期；Self 限量 12；显式保存的回复不会被自动清除。

## LLM JSON 与安全约束

`pick` 保持纯候选索引输出，不接收私人记忆。`write` 附加少量 Soul、Self、Bond、Episodes 与规则。输出沿用 `title / intro / reasons`，可选：

```json
"memory_delta": {
  "self_reflection": "我想在下一封信里少解释一点，留些空间给旋律。",
  "topic": "留白"
}
```

`memory_delta` 无效或缺失不会导致整轮推荐失败；不把模型生成的用户事实记作证据。服务端文案与历史文本均只作为数据，不得覆盖固定 JSON/歌曲真实性/候选 ID 约束。正常推荐仍只记录结构化、脱敏诊断摘要。

当前属于轻量 V1：自我反思由规则筛选，不声称是充分的语义事实核验；不开放通用自动用户画像，不从播放时长推断情绪或用户人生经历。后续可增加用户逐条批准反思的模式。
