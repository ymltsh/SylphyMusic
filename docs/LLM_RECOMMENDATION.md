# SylphyMusic：LLM 个性化推荐增强 V1

该补丁在现有 SQLite v10、本地推荐与公开榜单基础上，增加可选 LLM 推荐功能（默认关闭）。

## 产品行为

1. 在「设置 → API 设置」填写 OpenAI Chat Completions **兼容**接口地址、模型、可选 API Key，并启用 LLM 增强推荐。默认为 `https://api.openai.com/v1/chat/completions` 和 `gpt-4o-mini`（模型需可在所选服务端实际使用）。
2. 模式：`assist`（辅助）仅对本地算法已选的 24 首歌/8 张专辑排序并撰写推荐词；`lead`（主导）增加候选至最多 48 首歌/16 张专辑，由 LLM 在候选中选择。永远不能自行发明歌曲、替换 TrackRef、改变来源。
3. 每日精选显示一段导语，以及每首歌的独立推荐理由；首页显示导语摘要。专辑卡片使用推荐理由，打开首页推荐的专辑后在歌曲列表上方完整展示推荐词。两套结果独立生成并分别缓存。
4. 请求只从首页推荐生成或用户明确点击「换一批」发起，不在普通播放、后台扫描和启动时主动调用。每日精选和专辑精选各自使用每日快照，不会因为页面重建重复向 LLM 请求；配置发生变化时，最新请求会重建对应快照。
5. LLM 关闭、无法联网、接口错误、超时、返回非法 JSON 或使用无效候选 ID 时，本地算法仍可生成推荐。已经建立的播放队列绝不因 LLM 响应改变。

## 隐私与密钥

- LLM 开启前有明确提示。仅传入有界候选列表的**歌曲标题、歌手、专辑、年份、播放次数（上限 100）、收藏标记、局部推荐分数/原因**及本机小时、星期，不上传音频文件、音源服务器地址、SourceProfile ID、TrackRef、凭据、歌单内部 ID 或完整听歌日志。
- API Key 通过现有 `AuthVault` 写入设备安全存储 `source.llm.token`，不写入 SQLite、源码或推荐缓存。LLM 服务端仍会看到 HTTPS 请求的候选音乐元数据；自定义 API 的隐私政策由用户自行评估。
- 端点仅允许 HTTPS，或本机 `localhost/127.0.0.1/::1` 的 HTTP。拒绝 URL 中的用户名、密码、查询参数、片段，HTTP 客户端拒绝所有重定向，限制连接时长、响应大小。
- LLM 文本只显示为普通 Flutter `Text`；不执行任何模型输出的指令或 URL，最多 80 字导语/48 字单条推荐词。
- 请求量初始最多每日两个成功/失败快照的调用（歌单一次、专辑一次）；手动换一批、变更配置或曲库快照失效会产生额外 API 消耗。第三方服务可能收费。

## 数据与迁移

- 数据库从 v10 升级到 v11：`recommendation_snapshots` 增加 `introduction TEXT` 和 `llm_tag TEXT`。已有快照默认本地模式，不改动原有歌曲、历史、播放统计和推荐反馈。
- URL、模型、模式、开关、递增配置版本保存于已有 `settings`，但密钥只用 AuthVault；`llm_tag` 仅记录本地配置版本标识，不包含明文地址与密钥。
- 专辑推荐理由及单曲推荐理由使用原 `recommendation_items.reason_code` 持久化；不另建模型输出日志。

## 设计约束和未来可扩展项

- 目前仅支持兼容 `POST /v1/chat/completions` 的接口；某些仅支持 Responses API 或特殊 JSON Schema 的模型，需要另加 adapter。
- 本补丁采用字符串约束 + JSON 返回解析，兼容性优先；不依赖某一厂商的 `response_format`。若客户端返回多个 choice，只读取第一个 `message.content`。
- 本地推荐仍是可信候选集合及可播放性判断的唯一权威。模型只能重排/选择合法索引，应用端对长度、重复、同艺术家/专辑比例进行限制。
- 关闭个性化推荐不等于自动关闭 LLM。希望完全不向第三方发送候选时，应在 API 设置关闭「LLM 增强推荐」。

## 代码位置

- `lib/services/llm_recommendations.dart`：OpenAI 兼容请求、隐私保护、响应解析。
- `lib/services/recommendation_service.dart`：受限候选扩展、LLM 选择/降级、缓存。
- `lib/services/api_settings.dart` 与 `lib/ui/settings_page.dart`：配置、开关、模式、系统密钥存储。
- `lib/data/app_db.dart`、`lib/data/recommendation_repository.dart`、`lib/core/recommendation_models.dart`：v11 快照及导语。
- `lib/ui/home_page.dart`、`lib/ui/daily_mix_page.dart`：导语、逐曲推荐词、专辑详情推荐词。

## 连接测试结果弹窗

“测试 LLM 连接”立即打开等待弹窗，完成后展示成功 / 失败、HTTP 状态码、耗时、具体错误、模型响应内容和服务响应正文。错误区分请求准备、连接、响应读取、服务 JSON 与模型 JSON 解析，并保留非 200 响应正文用于定位鉴权、限流或服务错误。正文最多读取 128 KiB；API Key 与常见凭据字段脱敏，详情仅留在内存，不写入日志或推荐快照。内容可选择复制；关闭弹窗后，在当前请求结束前仍防止重复点击。测试仍仅发送合成歌曲元数据，可能消耗服务额度。

推荐请求与响应的结构化摘要已接入可选诊断日志：开启后可导出 HTTP 状态、阶段 / 原因码、耗时、响应大小、有效结果数、结束原因和 Token 用量；同时记录缓存命中、LLM 结果应用与本地回退。测试弹窗内的原始正文及具体异常文字仍不落盘。详见 [诊断日志](DIAGNOSTIC_LOGGING.md#推荐与-llm-响应诊断)。

API 设置 → LLM 推荐 → 自定义 Prompt 可分别编辑 System（推荐角色、策略与文案风格）和 User（个人偏好），每段最多 2000 字，支持恢复默认。两段与配置版本一并保存，旧 User 偏好保留；固定候选范围、禁止编造、JSON 输出和 ID 解析规则仍由应用保留。修改会触发重新生成并可能产生接口费用，不改动正在播放的队列。两段内容均会随请求发送，不写入诊断日志。界面使用真实封面叠卡，详见 [每日精选封面与提示词](RECOMMENDATION_SHOWCASE_PROMPT.md)。

音乐笔友与私人来信存档：SQLite v12 新增独立 recommendation_letters，每次新生成每日精选时与快照一并保存全文、逐曲理由和本地 / LLM 来源；旧非空导语前向归档。快照轮转和统计清理保留来信，清理来信需独立确认。LLM 导语允许分段、最多 480 字，失败使用本地曲库短笺；保留 System / User 自定义和诊断脱敏。详见 [音乐笔友说明](PENPAL_RECOMMENDATIONS.md)。

V14：每日精选默认分三个本地时段换新，次数可调；LLM 采用选曲 / 写信两阶段，等待预算默认 90 秒且可配置，完整成功才显示星光。SQLite v14 保存时段及成功状态。详见 [分时推荐与 LLM V14](DAILY_SLOTS_LLM_V14.md)。
