# 发布标准与后续验收

2026-10-28 按维护者要求简化流程：“能跑就行”，并将验收从发布流程移除。此前 IMP-001 要求全部首版验收通过后才能发布的限制停止适用；未完成事项作为独立验收工作保留，不由发布脚本执行或解析复选框阻断正式版。

## 发布时做这些检查

1. 为本次分发的平台构建普通入口 Release 包；本次提供 Android / Windows，Linux 暂缓。
2. Android 使用固定正式证书且验签通过。Windows 当前允许未代码签名分发，发布说明注明。
3. 检查版本号、包内容、私密信息排除、运行依赖和 SHA-256，随包收集依赖许可文本。
4. 发布到 GitHub 并更新对应渠道清单，核对远端资产与本地摘要一致。已有本次发布授权时直接完成，不重复征求确认。

静态分析、单元测试、启动冒烟和人工 / 设备验收独立执行，可用 `tool/check_local.ps1` 或 CONTRIBUTING 中的命令；它们不是 `release.py` 的步骤或发布前置条件。Android / Windows 是 1.0 的发布范围，Linux 暂缓。测试版未实装，正式签名切换按全新安装处理。长期真机兼容性、全面协议矩阵、完整原生依赖许可审计和独立离线密钥备份继续跟进，发布说明如实列出限制。
