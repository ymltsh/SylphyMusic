# Android SAF 本地文件夹导入补丁

## 修复目标

Android 13（SDK 33）等设备选择本地目录后，原有 `FilePicker.getDirectoryPath()` 与 Dart `Directory.list(recursive: true)` 的组合可能返回零首。这个补丁使用原生 `ACTION_OPEN_DOCUMENT_TREE` 获取用户授权，通过 `DocumentsContract` 递归枚举树内文档；无需声明全局 `READ_MEDIA_AUDIO` 权限。既有 `file://` 桌面目录和单文件导入保持不变。

## 播放兼容性和存储代价

目前 SylphyMusic 的播放器、封面和歌词处理依赖普通文件路径，无法直接将 SAF `content://` URI 当作文件路径交给播放器。因此本补丁将音频与同名 `.lrc` 流式复制到应用私有 `sylphy_music/saf/<sourceId>/` 目录。后续扫描依据提供者报告的大小与修改时间复用未变化的副本。**会额外占用本机空间，首次导入大型曲库可能较慢**。移除来源时只清理应用创建的副本，不删除用户原始文件；未移除的来源会留存私有副本以供离线播放。若提供者不报告可信修改时间，重新扫描会重新复制文件。

## 数据保护

文件夹选择取消不会创建来源。初次零首不添加来源；重新扫描零首或抛出异常保留现有曲库（不会覆盖为零）。从“导入文件”进入的歌曲使用独立的 `file:///` 来源，不再混入某个 SAF 文件夹来源。扫描抛错不提交索引。已有文件夹来源可以重新扫描，授权失效时应重新添加文件夹；原 `file://` 来源暂不自动迁移。

## 验证建议

1. Android 13/MIUI：选择有 MP3、FLAC 及子目录的文件夹，应产生非零歌曲并正常播放。
2. 重启应用后重新扫描，未变化歌曲应复用私有副本；查看诊断日志 `scan_completed`、`result_count` 和候选数。
3. 移走 U 盘或撤销文档树权限后重新扫描，预期报错并保留旧索引。
4. 多次选择同一文件夹、删除其中一个来源，不应影响另一个来源的授权。
5. 测试单独导入、中文文件名、同名 LRC、同目录不同格式同名文件以及空间不足。
6. Android 9 车机、Windows/Linux 上既有 `file://` 本地文件夹导入应保留原行为。

注意：并非所有系统目录都可经 SAF 选择，例如受 Android 11+ 限制的部分目录。设备上的授权、导入和播放行为仍待用户验收，本地编译记录见 [实施与验证记录](PROGRESS.md)。
