# Letter UI v13 — implementation notes

## Contract

- `LlmSelection.title` is optional for old OpenAI-compatible providers; response prompt asks for a distinct, genuine title for each daily letter. Only daily (not album) title is used.
- Fallback title remains stable when LLM is disabled, returns malformed JSON, or omits title. Title is never generated by interpolation from raw candidate metadata.
- `DailyMix.title` comes from the persisted daily snapshot, not from a new model request on Widget rebuilding.
- `RecommendationLetter.title`, `coverRefs` and `trackCount` survive snapshot pruning. Only the display string and four source-scoped TrackRef keys are retained; no music credentials, URLs, or media bytes are stored in SQLite.
- Export settings are stored in existing settings records; title/cover references require forward-only SQLite v13 migration.
- For historical records with removed sources, images gracefully fall back to letter text or placeholder covers. A missing source is not replaced by an equal title from another server.
- `LetterImage.render` paints the full content using Flutter Canvas + TextPainter and includes the app logo, date, title and cover collage; it does not render from the currently scrolled widget area.
- Preserve existing per-track reasons, manual regeneration, playback queue identity and daily snapshot semantics.

## Suggested acceptance (user-owned validation)

1. Android portrait 360–420 dp: outside-card duplicated day/count removed, card owns headline; playback action remains accessible.
2. Same day with LLM enabled: after “换一批”, different generated letter titles may appear; after restart the same title is retained.
3. Saved archive: title and 4 card covers remain after current snapshots are pruned; if source deleted, no replacement by title occurs.
4. Export settings: toggles and theme survive app restart; image contains real card covers and full content, with no cropped paragraphs.
5. Sharing saves local PNG first and opens the platform share sheet; exported image has four-cover positions/rotations matching in-app layout.
6. v12→v13 migration preserves existing snapshots and letters and does not delete the music database.

## Unified export and footer actions

The single Export button opens configuration on every invocation, prefilled with the last choices. Confirming saves to the local gallery / Pictures; optional sharing defaults off. Cancelling creates no image. Daily letter metadata and Play all / More actions now appear beside Export at the end of the letter, after the song notes. Exported PNG metadata is also in the branded footer.
