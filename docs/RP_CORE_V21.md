# RP Core v21：角色状态、条件世界书与可信记忆

## 一、动机

v20 将每条用户聊天作为 `chat_preference` 且 `pinned=1` 保存，旧 `PenpalMemory.writeContext()` 又将最近的个人偏好、自我反思、历史来信、话题直接交给 LLM，容易使“苹果酿”之类一次性闲聊在未来的信件中被反复提起。v21 将保存聊天和记忆分类解耦。

## 二、运行时边界

- `RpRepository`：持久化状态、用户确认的事实、情节、世界书、时间戳和来源；所有查询以不可变角色卡 `card_id` 隔离。
- `RpRuntime`：提供角色状态、关键词 Lore 激活、精简事件/记忆召回、话题冷却及只在前台的 Event Director。
- `PenpalChatPage`：RP 状态管理页提供稳定的 `rp:general` 独立会话入口，不依赖音乐来信，且清空音乐档案不删除该线程。
- `PenpalChatService`：向模型追加 RP Context；成功且用户选择“记住”时保存聊天并记录派生记忆。生成成功后才记录；保存原对话失败不写派生记录。
- `PenpalMemory` 兼容桥：旧“保存给笔友”的来信回复改写到新 RP `user_reply` 类型，不再增加旧表；清空信件档案时清除相关 RP 派生记忆。
- `RecommendationService`：仍先本地召回真实曲库、再由 LLM 选曲/写信；写信输入 RP Context、经确认的偏好和真实候选。推荐入库后记录话题与短期“写过信”经历。
- `PenpalMemoryPage`：原路由名保留，但内容指向独立 `RpManagementPage`，可编辑角色状态、固定或删除记忆、调整世界书与事件、手动结束话题。

## 三、数据模型

SQLite v21 新建：

| 表 | 作用 | 身份 / 约束 |
|---|---|---|
| `rp_character_state` | 场景、活动、目标、精力、开关 | `card_id` PK |
| `rp_memories` | `preference/episode/reflection/agreement/user_reply`，来源、重要度、过期与固定 | `card_id`、`conversation_key` 绑定聊天来源 |
| `rp_lore_entries` | 关键词世界书 / 随机事件候选，优先级、概率和冷却 | `card_id`, `kind` |
| `rp_topics` | `active/cooling/resolved` 及冷却时间 | PK(`card_id`,`topic_key`)，带 `origin` |
| `rp_event_instances` | 具体发生的虚构 RP 事件，`active/resolved` | 按卡独立 |
| `rp_event_rolls` | 当天是否已尝试随机事件 | PK(`card_id`,`local_day`) |

手动固定的记忆可长期保留；短期 `episode` 默认 7 天过期，且非固定实例最多 32 条。随机事件按每日固定种子（卡 ID + 当天）抽取，最多尝试一次，事件卡自带概率和最短间隔；过期活跃事件自动结束。

## 四、上下文组装顺序

1. **固定 System**：使用现有角色卡，不允许自由修改候选 ID、来源安全、JSON 输出约束。
2. **当前场景与活动**：角色状态永远独立于用户偏好。
3. **长期偏好**：只注入已手动固定、明确第一人称表达且未关闭记忆的有限记录。
4. **短期经历**：只有当前用户文本与情节出现具体词语重合才注入；不会因为时间近就自动复述。
5. **条件世界书**：仅关键词命中时激活最多四条设定。
6. **随机事件**：至多一条活跃事件，标注为 RP 虚构情境；允许角色忽略。
7. **话题冷却**：将近期结束 / 冷却主题作为禁止主动复述清单；用户重新提出时允许讨论。
8. **当前消息**：优先级最高，模型必须自然回应而不是朗诵一份状态表。

## 五、旧数据迁移

**没有兼容导入。** `onUpgrade(<21)` 先清空旧推荐与 RP 交互表，再新建空的 RP v21 表。`onCreate` 直接建新表，正常新建数据库无需清理。角色卡、音源/曲库、歌单、收藏、凭据、播放队列和最近播放 1000 身份列表不在清理范围。

旧存档不可在 App 内继续查看；以便旧“事实”与记忆不会污染新架构。独立备份需用户自行管理。

## 六、仍属轻量版的限制

- 不会推断所有聊天的完整语义；长期偏好只从明确表达中保守提取，用户也能手动创建。
- 不做虚构事实的自动真实性判定；随机事件在 Prompt 中明确标记为虚构 RP 场景。
- 世界书触发是简单关键词，不含正则逻辑与 Risu/SillyTavern 全部高级规则。
- 不运行常驻智能体、计划调度器、向量数据库或自动联网搜索；音乐热门榜与 RP 事件相互独立。

## 七、需要用户设备验收的关键情境

- 升级前备份数据库，升级后核实旧推荐和旧聊天确实清空；原角色卡、歌曲、歌单及最近播放列表保留。
- 新聊天中讨论苹果酿后，下一轮无关来信不主动提起；用户主动重提时可以自然回应。
- 不同角色拥有独立世界书和故事；切卡后不会混用事件或记忆。
- 同一天反复进入聊天/来信，不会重复触发事件；结束事件后上下文不再携带。
- 删除聊天可清除对应派生记忆；删除角色卡会清理其 RP 数据。
- LLM 失败不影响本地推荐或音频播放；没有音乐也可以聊天。
