# Emby 歌词时间轴

Emby 内嵌 `text` 歌词的 `Stream.txt` 可能只返回文字，原始时间轴被服务端转换去掉。已对用户指定的歌曲只读验证：TXT 无时间标记，SRT 有 55 条时间记录；LRC / VTT 转换在该样本上返回空内容，JSON 格式不存在。因此不能把 TXT 当作原始 LRC，也不应因为 LRC 转换为空就认定歌曲没有同步歌词。

## 获取与转换

- 每曲刷新 MediaSources / MediaStreams，通过来源认证头请求对应 Subtitle 索引，保留服务器路径前缀；不跟随未验证的重定向，不信任流中的任意外部地址，不下载整首音频取词。
- 外置 LRC 优先原格式；内嵌 text / txt 和其他文本字幕优先 SRT，再回退 TXT。兼容 Items / Videos 两种同源路由。不支持格式可回退，鉴权和服务器错误保持错误语义。
- SRT / WebVTT 的小时、分钟、秒和毫秒统一转为 LRC，保留原始起始时间；同时间译文保持原顺序并合并展示，字幕标签不会出现在歌词里。存在间奏空档时按结束时间插入空行，避免上一句持续高亮。
- SRT 结束时间等于或早于开始时间时，保留起始时间与文字，不生成结束清空标记，兼容纯音乐提示。读取现有 Emby 自动缓存时同样归一化，无需清空缓存；手动导入仍按原文优先读取。
- 单次歌词响应仍限制为 1 MiB。正常 LRC 和纯文本不被当作字幕控制信息处理。

Emby 官方说明：[文本字幕的格式转换接口](https://dev.emby.media/doc/restapi/Subtitles.html)。

## 缓存与手动导入

Emby 服务器结果使用 `.emby-timed-v2.lrc` 独立缓存。有时间轴的缓存直接复用；无时间轴的服务器缓存会在下次打开时尝试重新获取，以兼容服务器后续补齐歌词。原有无时间轴文件保留为网络失败 / 无新歌词时的回退，不删除原内容。现有有效 LRC 继续直接使用。

新手动导入使用 `.manual.lrc`，优先于服务器缓存且不被网络刷新覆盖。旧版把自动缓存与手动导入存在同一文件，无法可靠区分来源：旧纯文本会尝试升级并保留原件；若仍需优先使用此前手动导入的无时间轴文本，重新导入一次即可。原始外部歌词文件不修改。

## 验证

- `test/emby_lyrics_test.dart`：带时间格式优先、路径前缀 / 认证头、LRC、旧路径、不支持格式回退与权限错误。
- `test/lyrics_test.dart`：小时 / 毫秒、多行译文、间奏、重叠字幕、VTT 设置与原 LRC / 文本保留。
- `test/lyrics_cache_test.dart`：旧文本升级和原件保留、版本缓存复用、手动导入优先、网络失败回退、服务器后补时间轴与旧 LRC 离线读取。
- 私密实服响应留在 Git 忽略的 `.private/`，用本地响应快照逐条核对 55 个起始时间，不把真实歌词、曲目身份、地址或凭据加入测试源码与包内。
