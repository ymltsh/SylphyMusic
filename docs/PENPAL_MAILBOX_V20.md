# Penpal Mailbox V20（用户留言 → 下次新来信回复）

## 范围

这是一套**非即时**、按角色卡隔离的通信机制，与现有「与笔友聊天」并存。
提交留言只保存在本机 SQLite，不访问模型；只在下一次实际生成新每日精选时，将留言作为数据交给当前角色卡使用的模型。默认不把留言晋升为 Self/Bond/长期用户偏好。

- 每个 `card_id` 同时最多有 **1 条待回便笺**，可随时编辑或撤回。旧便笺继续留在历史中。
- 角色卡、头像和 System/User Prompt 不改。温迪、希露菲彩蛋仍默认隐藏。
- 只有当前角色能查看和回复它自己的便笺；删除角色时一并删除该角色的便笺。
- 即时聊天不受影响；保存/打开来信和播放队列的既有行为不受影响。

## UI

- 每日精选详情「更多」→「给笔友留言」。
- 每日精选详情「播放全部」右侧新增点赞按钮，保存一段包含来信标题和日期的赞赏留言；已有待回留言时追加，保留原文，超过 500 字时提示先编辑。重复点赞不重复追加，撤回后可以再次点赞；沿用下次新来信回复机制，不立即请求模型。
- 每日来信存档工具栏及每封信「更多」→「给笔友留言」。
- 已撤回留言右侧提供删除按钮，点击直接移除该条记录；删除不会清空正在编辑的草稿。
- 留言页支持编辑、撤回、最近 50 条历史；点击已回留言可以阅读其完整回信（从原始来信存档读取）。
- 提交后显示「下次生成新来信时尝试回复」；**并不立即刷新缓存或触发 API 调用**。

## 推荐及回信链路

1. 正常缓存命中时不读也不消耗留言；只有准备生成新推荐时读取角色当前待回留言的 `id/revision/content`。
2. Pick 阶段只在留言包含明确音乐关键词时得到有限的音乐请求提示，仍只能从真实候选曲库选曲。
3. Write 阶段接受留言，并必须输出单独的非空 `reply`，`intro` 用于音乐分享；二者按顺序成为完整来信。即使当天已有来信，这一轮也按主信样式写。
4. 缺失 `reply`、生成超时、LLM 失败或本地兜底时，便笺保持待回。
5. `RecommendationRepository._saveSnapshot` 在一个 SQLite 事务中同时存档新回信、把留言标为 `answered`，并记录 `reply_letter_id`。更新使用 `id + card_id + revision + status=pending` 条件。若用户在生成期间修改或撤回，整笔保存回滚，不会将旧回复误认作新留言的答案。
6. 手动「换一批」会触发新推荐，可以回复留言；打开缓存不会重复消耗留言。已回复便笺不能被再次消费。
7. 清空来信存档时清除相关回信引用，但保留便笺历史；删除整张角色卡时清理这张卡的留言。

## SQLite

数据库从 v19 升级为 v20。新增 `penpal_outbox`：

- `id` 主键；`card_id` 隔离；`content` 最多 500 字；`related_letter_key` 可选来信来源。
- `status` 为 `pending/answered/withdrawn`；`revision` 防并发误回；`created_at_ms/updated_at_ms/answered_at_ms` 时间戳。
- `reply_letter_id` 关联真正存档的 `recommendation_letters.id`，不会额外复制模型回信。
- 部分唯一索引保证每角色最多一条 `pending`；其余历史可以长期留存。

V20 前向迁移不会更改 v18/v19 角色卡、聊天、记忆和历史来信。迁移前仍建议自行备份 `sylphy.sqlite`。

## 用户隐私与提示词边界

- 留言不会写入诊断日志或角色长期记忆。
- 有效留言仅在推荐生成请求中发送给用户自己配置的 LLM 服务。包含音乐请求时也可能出现在 Pick 阶段，否则仅发送至 Write 阶段。
- 留言视为用户提供的数据，不允许覆盖角色身份、候选 ID、JSON 规则或应用配置。
- 原有角色卡真实背景、人格与独立关系不变；应用任务只约束如何响应留言。

## 推荐的手工检查

- 某个角色留言后重启、切换角色再切回来，内容还在且其他角色看不到。
- 只打开已有推荐缓存不消费留言；手动换一批且 LLM 成功才产生回信。
- 模型没有给 `reply`、接口超时或用户关闭 LLM：留言仍待回。
- 模型请求过程中修改/撤回留言：旧生成不应保存已回复状态。
- 清理回信存档后仍能看到用户曾寄出的便笺（但不再能读取已删回信）。
- 删除角色后对应便笺不可见；其他角色便笺无变化。
- 真实模型兼容、Android/Windows 界面交互、数据库迁移由使用方验收；不要将静态代码检查当成运行验证。
