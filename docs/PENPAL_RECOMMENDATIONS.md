# 每日精选的音乐笔友文案

## 体验

像老朋友通信：问候 → 分享从曲库注意到的 2–3 首歌与真实选择理由 → 留有余地的收尾。不是「你应该听」，也不假装已经亲耳听到歌曲、记得用户经历。首页显示来信摘要，详情页展开多段全文；逐曲理由仍紧邻歌曲。

## Prompt 层级

- System 默认使用音乐笔友角色，并按用户既有要求保留角色、策略和语气自定义；可信候选 ID、真实性、JSON 协议、书信及推荐词字数由应用追加固定约束。
- 可编辑 User：笔友口吻、希望多探索哪些作品、是否喜欢诗意等。可以影响选曲和文字风格，不允许突破 System 约束。
- 系统数据：最多 48 首受限候选、收藏和播放概况、所在本地时段、可选缓存每日一言、真正匹配上的公开榜单热度分。每天一言可能是缓存，不作为今日事实；网络热度只有信号，不可声称精确排名。

## 存档与清理

SQLite v12 的 `recommendation_letters` 与 `recommendation_snapshots` 分离。每次新生成一轮每日精选（包括手动换一批）在快照事务里追加信件；重复阅读不写入。快照按既有上限清理时存档保留。清空推荐统计不删除信件；信箱提供独立清空操作。旧的非空导语在迁移时归档。离线/LLM 失败时生成基于曲库真实名字的本地信件，并标示来源。

## 边界

- 当歌曲名字或推荐候选为空时没有信件记录；不会发明歌曲。
- 导出诊断日志不包含信件原文；信件属于私人应用数据。卸载应用或清除应用数据将删除存档；用户自行备份数据库才能迁移。
- 当前无真实仓库工作区、Flutter/Dart 编译器；补丁未验证编译。按照仓库 AGENTS.md，不在本轮运行自动测试或发布。

本地合并适配：保留“自定义 Prompt”的 System / User 双段编辑与事务保存。每日精选轮次同时参考存档，避免清空推荐统计后轮次重用导致保存冲突。分页读取与清空互斥，首次读取失败可重试。

## 导出图片与分享

今日音乐信及历史信件均支持“导出图片”“分享图片”。PNG 根据完整正文排版，底部署名为风灵音乐 · Sylphy Music、信件日期与项目 Logo。默认保存在系统 Pictures/SylphyMusic；Windows 使用已知图片目录（兼容重定向），Android 10+ 使用 MediaStore，Android 9 及以下按需请求写存储权限。分享会先保存本地图片，再由用户在系统分享面板选择目标。重复导出用独立时间戳保留文件；导出 / 分享失败显示提示。
