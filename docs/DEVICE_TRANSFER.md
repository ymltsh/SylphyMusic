# 设备间快速迁移（v1）

Android / Windows 之间的临时局域网迁移。**不是后台同步或设备备份**；双方需主动打开迁移页面，所有监听和扫描在离开页面后释放。

## 操作

1. 新设备首次启动：欢迎页 → 第二页独立迁移欢迎引导 →「从旧设备迁移」；或设置 → 设备间快速迁移 → 接收。首次使用可点「首次使用，手动设置」继续选择音乐源及 API。全部配置导入成功后完成引导，仅导入音乐源则继续 API 配置，取消接收返回迁移欢迎页。
2. 旧设备：设置 → 设备间快速迁移 → 发送，选择「全部手动配置」或「仅音乐源」，从雷达或列表选设备。
3. 核对两端相同的 6 位数字，两边都确认；接收端再次预览并确认导入。
4. 目标端仅添加不存在的远程来源，不覆盖现有服务器账号。重启应用以刷新可能延迟生效的自定义角色卡、设置等。

## 范围

- 仅音乐源：远程来源的协议、地址、用户名、WebDAV 范围及必要 Token/密码/身份凭据。
- 全部手动配置：以上内容、白名单内的 API 地址及 LLM Prompt、LLM/LrcApi 密钥、主题颜色/歌词字体、自定义播放器模板、背景图片、已存在的音乐笔友角色卡（含头像）。
- 不迁移：歌曲文件、本地音乐目录、歌曲索引、缓存、播放队列、收藏和歌单、收听历史、任何布尔开关、后台任务、诊断日志。新设备需重选本地音乐目录并在必要时重新授权云音乐服务。

## 网络与安全

- 默认使用 UDP IPv4 广播发现（43872），接收端监听一个系统分配的随机 TCP 端口。局域网中无法互通的子网、访客 Wi-Fi、AP 隔离及 Windows 防火墙会阻止设备发现。
- 发现广告只包含随机临时 ID、临时端口和设备名，不含配置和密钥；停止接收后立即关闭广告。
- 设备名使用常用音符与六位随机设备编号，例如「♫ 设备 482913」，不读取系统主机名。同一次接收期间名称固定，接收页与发送端发现列表显示相同名称；重新打开接收页生成新名称。设备编号只用于识别设备，配对时仍需核对会话生成的配对码。
- X25519 临时公钥交换、HKDF-SHA256 派生密钥、AES-256-GCM 加密每条消息；配对码由有序握手 transcript 哈希生成，必须人工比对。双方确认后才会传送配置。
- 单条传输上限 64 MiB，配置 JSON 上限 48 MiB，背景图上限 40 MiB，角色卡头像上限 8 MiB。不输出明文密钥到日志。
- 不允许公网 IPv4 直连。源设备不删除任何原始数据。目标端先验证输入，重复来源跳过；失败会尽量回滚新增来源、凭据和数据库设置。

## 接收页故障排除

接收页右上角帮助按钮、等待状态的「找不到本机？故障排除」及错误状态均可进入独立排障页。按问题分卡展示本机名称、接收阶段、UDP / TCP 监听、连接占用与局域网 IPv4 接口信息，并可刷新。这里不向其他设备发送探测请求；监听成功不能证明跨设备网络已畅通。

Windows 提供用户点击触发的「自动修复」、打开防火墙及可复制的管理员命令。自动修复通过系统 UAC 提权，仅添加或更新 `SylphyMusic.Transfer.Discovery` / `SylphyMusic.Transfer.Receive` 两条规则，限定当前可执行文件、专用网络与 LocalSubnet；发现规则使用 UDP 43872，TCP 接收按程序放行以适配临时端口。不会关闭防火墙或修改网络类型，组织策略与公用网络仍需用户自行检查；修复结果仅说明规则是否写入，不能替代连接验收。开发构建期间不执行修复或修改主机规则。

Android 可重新请求现有本地网络权限。通用说明覆盖同网、访客隔离、VPN / 路由、版本不一致、配对与断连。等待或错误时可返回并重新开启接收，已开始连接 / 导入时不重启当前会话。排障页面保留接收服务，回到接收页继续配对；退出接收页面时才关闭。

## 注意与验收

- 这是单次迁移，不替代云端实时同步。外部服务器访问令牌可能绑定设备，因此导入成功不保证每个来源免登录。
- 对端版本不能识别的数据格式时拒绝迁移，而不是直接复制 SQLite 文件。
- 测试：`flutter test test/device_transfer_test.dart`；还需真机/真 Windows 验证发现、防火墙、后台离开、中途断连、权限拒绝、重复来源与不同版本播放器布局。
- Windows 第一次接收可能弹出本地防火墙询问；Android 17+ 通过本地网络权限请求。设备雷达点仅用于展示，不代表真实地理方位或距离。
